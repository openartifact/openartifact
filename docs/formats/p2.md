# Eclipse p2

Use a p2 repository to build Eclipse plug-ins and RCP products with Tycho, to install into the Eclipse IDE, or to provision with the p2 director from an update site through your own server. The proxy caches every bundle, feature and metadata file once, keeps the client on OpenArtifact even when the update site points at mirrors, and applies [curation](../repositories/hosted-proxy-group.md#package-curation) to bundles and features.

| Item | Value |
|---|---|
| Client URL | `https://HOST/repos/p2/REPO/` (with the trailing slash) |
| Format id | `p2` |
| Repository types | [proxy](#create-a-proxy-repository) only |
| Default upstream | none: you name the update site |

There are no hosted p2 repositories, and no group repositories: creating either is refused with `400 validation_failed`. To combine several update sites, publish a composite repository upstream, or add one proxy repository per update site to the build. Nothing is uploaded to OpenArtifact. Cached files are shown in the repository's cache listing and are evicted with the usual [proxy cache controls](../repositories/hosted-proxy-group.md#cache-ttls).

## Create a proxy repository

Give the base URL of the update site as `upstream_url`: the directory that holds `p2.index`, `content.jar` or `compositeContent.jar`, and `artifacts.jar` or `compositeArtifacts.jar`.

Web UI: choose **New repository**, type **Proxy**, format **Eclipse p2**.

API:

```sh
curl -X POST HOST/api/v1/repositories -H "Authorization: Bearer <TOKEN>" \
  -H 'Content-Type: application/json' \
  -d '{"name":"eclipse","format":"p2","repo_type":"proxy","upstream_url":"https://download.eclipse.org/releases/2024-12"}'
```

Declarative config, applied with `oa apply -f eclipse.yaml` ([declarative config](../integrations/declarative.md)):

```yaml
apiVersion: openartifact.io/v1
kind: Repository
metadata:
  name: eclipse
spec:
  format: p2
  repo_type: proxy
  upstream_url: https://download.eclipse.org/releases/2024-12
```

The repository fields are described in [creating repositories](../repositories/hosted-proxy-group.md#creating-repositories). An update site that needs a login takes `upstream_username` and `upstream_password`; they are sent only to the update site's own host.

## Client setup

Create an OpenArtifact API token as described in [authentication](../security/authentication.md); read access is enough. Send it as the password of a Basic login. The web UI connect panel shows the same commands with your own URL.

Tycho, in `pom.xml`:

```xml
<repositories>
  <repository>
    <id>eclipse</id>
    <layout>p2</layout>
    <url>https://HOST/repos/p2/eclipse/</url>
  </repository>
</repositories>
```

and the credentials in `~/.m2/settings.xml`, in a `<server>` with the same `<id>`:

```xml
<settings>
  <servers>
    <server>
      <id>eclipse</id>
      <username>USERNAME</username>
      <password>TOKEN</password>
    </server>
  </servers>
</settings>
```

Eclipse IDE: **Help > Install New Software > Add...**, then enter `https://HOST/repos/p2/eclipse/` as the location. The IDE asks for the user name and token the first time and keeps them in its secure storage.

p2 director:

```sh
eclipse -nosplash -application org.eclipse.equinox.p2.director \
  -repository https://HOST/repos/p2/eclipse/ -installIU org.eclipse.equinox.common
```

A server with `allowAnonymousRead` and a public repository need no credentials.

## What the proxy rewrites

A p2 repository is a tree of static files. The proxy caches them under the path the client asks for, and rewrites only the repository documents that would send the client somewhere else:

- **Mirrors and statistics.** `p2.mirrorsURL` and `p2.statsURI` are removed from the repository properties of `artifacts.xml`, `artifacts.jar` and `artifacts.xml.xz` (and the composite documents). The first makes the client ask a mirror finder and download from whichever host it names; the second reports every download to the update site. The `size` of the `<properties>` element is corrected. Properties of single artifacts are not touched.
- **Composite children.** A composite repository (`compositeContent.*`, `compositeArtifacts.*`) names child repositories. Eclipse release sites use paths such as `../../technology/epp/packages/2024-12/`, which leave the repository. The proxy rewrites each child on the update site's host so that it resolves under the proxy: inside the repository as a relative path, outside it as `_host/<path>`. See [the `_host/` namespace](#the-_host-namespace).
- **Everything else is passed through byte for byte:** `p2.index`, `content.*` (the metadata), bundles, features, `.pack.gz` files and checksums. The proxy never rewrites the metadata a client verifies.

The rewritten document keeps its encoding (plain XML, a jar holding one XML file, or an xz stream) and is cached in that form. A document that is not a p2 repository, such as an HTML page from a captive portal or an XML file with a `DOCTYPE`, is refused with `502` and not cached.

## The `_host/` namespace

A composite child on the same host as the upstream but outside its base URL is served as `https://HOST/repos/p2/REPO/_host/<path>`, which the proxy fetches from `scheme://UPSTREAM-HOST/<path>`. This is how the Eclipse release composite reaches `technology/epp/` next to `releases/`.

Because of this, the repository gives read access to every path on the upstream host that it can fetch, not only below `upstream_url`. Choose an `upstream_url` on a host that you would proxy entirely, or restrict the repository to the people who may read from that host. A `..` segment never escapes: the proxy refuses it.

Children on another host, any location with a query string, and any location with an empty path segment (`a//b`), are left unchanged: a client that resolves such a child contacts that host directly, bypassing the proxy. Add that site as its own proxy repository and reference it in your build instead.

## Caching

- **Bundles and features** (`plugins/`, `features/` and `binary/`) are named by id and version and never change: they are cached for good, and a repository with a [download redirect](../repositories/hosted-proxy-group.md) hands them out as object-store links.
- **Metadata** (`p2.index`, `content.*`, `artifacts.*`, `composite*.*`) uses the repository cache TTL, so a new release of the update site appears within `cache_ttl_seconds`. Metadata is capped at 256 MiB after decompression.
- A missing file answers `404`, as the p2 client expects when it probes for `compositeContent.xml` before `compositeContent.jar`.

## Minimum age and curation

Rules follow [Package curation](../repositories/hosted-proxy-group.md#package-curation). The format-specific parts:

- **Names.** A rule names a bundle or feature by its id as the file name spells it, for example `org.eclipse.core.runtime`.
- **Versions.** The version is the OSGi version from the file name, for example `3.31.0.v20240101-1200`.
- The upstream metadata gives no publish time, so `min_age_hours` has nothing to test and is ignored for this format.
- Curation blocks the download of a bundle or feature file. A client that has the metadata can still resolve a blocked bundle and then fails on the download with `403`.
